## 三、未打通的断点（按今天打包的必要性排序）

### P0-1 模板管线在客户机无法执行（最大断点）
- **现状**：template-route.ts 的 `PYTHON` 在桌面环境被 runtime-env.cjs 设为 `zhiheng-editing-worker.exe`（PyInstaller，stdin JSON job 协议、**忽略 argv**）。step1_decrypt / step4_fill / step5_verify 是独立 .py 脚本，客户机无 Python 可执行。
- **影响**：客户机上「按模板剪视频」会在 step1 解密即失败。
- **方案**：把 step1/4/5 合并封装为独立 CLI（`template-pipeline-cli.py`，子命令 decrypt/fill/verify），用 PyInstaller 打成 `template-pipeline.exe` 装配进 runtime/tools/；template-route.ts 执行层改为 `ZHIJING_TEMPLATE_PIPELINE` 环境变量解析。**不碰 worker 主链路**（新增独立 EXE，符合"不改剪辑主链路"约束）。

### P0-2 企业模板资产 + 母版草稿未随包/随数据包分发
- **现状**：`template-asset.json` 在开发机 `D:\知衡智企数据库\知识库\90_模板\企业模板\`；`sourceDraftDir = C:\Users\Administrator\Desktop\8月28日`；17 个素材 `assetPath` 指向开发机 `D:/知衡智企数据库/知识库/30_素材资源/视频库/...`。客户机全部不存在。
- **方案**：① 企业数据包（不进 Setup.exe）：企业模板目录 + `30_素材资源` 视频库 + 母版草稿副本，用户拷到客户机数据目录；② template-asset.json 的 sourceDraftDir / mediaPlan 改为**相对路径**，loadTemplateAsset 时按运行时数据根（DB templateRoot / ZHIHENG_ASSETS_ROOT）重映射；③ DB 首次初始化把 templateRoot 指向客户机数据目录。

### P0-3 前端契约不匹配
- **现状**：overview-page 调 agent-run 后要求 `payload.task`（异步任务模型），模板分支同步返回 `{route, ok, draftName, ...}` 无 task → 前端抛「自动剪辑任务创建失败」。
- **方案**：agent-run 模板分支返回兼容 `task` 字段（`{id: draftName, status: 'completed', title}`）+ 模板信息；前端展示「草稿已生成，打开剪映验收」。不改异步任务模型（Agent-native 保持原样）。

### P0-4 skills/template-editing 未进桌面 runtime
- **现状**：prepare-runtime.mjs 只装配 `skills/video-editing`。桌面版 skill-loader 的 `PROJECT_TEMPLATE_SKILLS_DIR = cwd/skills/template-editing` 不存在 → 落到 legacy 旧风格 skill。
- **方案**：prepare-runtime 增加装配 `skills/template-editing` → `next-server/skills/template-editing`（cwd 命中即加载三层 Skill）。

### P1（今天建议完成）
- **P1-1 本机安装版回归**：全链路重打包 + 本机覆盖安装 + 指定模板跑通 + 剪映打开。
- **P1-2 企业数据包组装**：模板目录 + 素材 + 安装说明 → zip（供客户机部署）。
- **P1-3 素材路径重映射落地**：loadTemplateAsset 支持相对 mediaPlan（数据根拼接）。

### P2（后续轮，今天不做）
- Template Route 接 TTS + 字幕（SOP 第 5 步；首版客户机验收口径与 8月28日 一致：先画面+文字，配音后补）。
- 素材语义检索 retriever（SOP 第 6 步）。
- LLM 受约束文案生成（客户机设置页配置 LLM 后自动启用；今天可用资产内置 replacementPlan 文本兜底）。
- 模板管理 UI（入库/验收/多模板）。
