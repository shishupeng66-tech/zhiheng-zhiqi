## 2. 表结构（Schema）

文件：`src/lib/db/schema.ts`

**`provider_profiles`**（供应商档案）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | text (pk) | 主键 |
| module | text | `llm` / `voice` / `material` / `video_engine` |
| provider | text | 供应商标识，如 `doubao` / `openai` |
| enabled | integer(0/1) | 是否启用 |

| created_at | integer | 创建时间 |
| updated_at | integer | 更新时间 |

唯一约束：`unique(module, provider)`。

**`provider_settings`**（键值配置）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | text (pk) | 主键 |
| profile_id | text (fk → provider_profiles.id, cascade) | 所属档案 |
| key | text | 配置键 |
| value | text | 配置值（机密字段为密文） |
| is_secret | integer(0/1) | 是否机密 |
| created_at | integer | 创建时间 |
| updated_at | integer | 更新时间 |

唯一约束：`unique(profile_id, key)`；外键级联删除。

> 注：第一阶段曾发生 `updated_at` 列名误写为 `created_at` 的复制错误，已修正，迁移 SQL 中两列独立。

## 3. 加密方案（Crypto）

文件：`src/lib/settings/crypto.ts`

- 算法：**AES-256-GCM**。
- 参数：IV = 12 字节，authTag = 16 字节；存储格式为 `base64(iv + authTag + ciphertext)`。
- 主密钥 `resolveMasterKey()` 解析顺序：
  1. 环境变量 `SETTINGS_MASTER_KEY`（hex64 / base64 的 32 字节）；
  2. gitignored 引导文件 `data/.settings-master-key`（若不存在则随机生成，权限 0600）；
  3. **主密钥不硬编码、不入库**。
- `encryptSecret(plaintext)` 返回密文；`decryptSecret(payload)` 还原明文。
- `maskSecret(value)`：保留前 4 位 + 后 4 位，其余以 `•` 掩码（短值显示 `••••`）。
- **现场验证**：DB 中 `DOUBAO_SPEECH_API_KEY` 值为 `TA1UzDoKCbluY+dz…`（密文），非明文 UUID。

## 4. 设置 API

文件：
- `src/app/api/system/settings/route.ts`
- `src/app/api/system/settings/[module]/route.ts`

- `GET /api/system/settings`：返回全部模块（掩码后）+ `videoEngine` 状态；不返回明文。
- `POST /api/system/settings`：`action: 'test'`，按客户端给定或回源 DB 默认供应商解析机密后做连通性测试，仅返回 `{ ok, message, latencyMs }`，**绝不回传密钥**。
- `GET /api/system/settings/[module]`：返回该模块掩码后的键值。
- `PUT /api/system/settings/[module]`：校验数组结构 → `applyModuleConfig` 写入（机密字段加密）→ 若为 `voice` 模块则调用 `syncVoiceServiceBridge()` 同步桥接文件。
- 所有路由 `runtime = 'nodejs'`，`super_admin` 专属（非超管返回 403）。
