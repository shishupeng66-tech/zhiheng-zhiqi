> **文档性质**：审计 + 设计（本轮**仅审计 + 设计，不修改代码**，不新增/修改 DB 表、`.env`、页面、按钮、不接 LLM、不改 TTS/MPT，不 commit/push）

## 0. 一句话结论

当前**没有任何统一模型/接口配置中心**：配置散落在「`.env.local`（明文）」+「MPT 自带 `config.toml`（未被桥接）」+「Voice Service 读 `.env.local`」三处，且**没有 LLM 真实入口、没有设置页、没有相关 API 路由、没有 `src/lib/ai|integrations|settings|providers`**。本方案据此设计一个以「加密 DB 为主存储 + super_admin 独占」的「模型与接口设置中心」，并把业务层收敛到统一能力层。

## 三、LLM 现状（明确回答）

- **目前知衡智企有没有真正的「统一 LLM 模型入口」？→ 没有。**
- 证据：① 无 `src/lib/ai`；② `.env.local` 无任何 LLM key；③ 检索 openai/deepseek/LLM 业务调用 0 命中；④ `ai-chat` 是脚本 Mock、`chat` 是本地 Mock（见 API 审计报告）；⑤ 自动剪辑脚本生成依赖 MPT 内部 LLM，但 MPT `config.toml` 的 `llm_provider`/`moonshot_api_key` 等为**空** → 实际也未生效。
- **结论**：当前「AI 聊天 / Agent / 自动剪辑脚本 / 知识问答」都没有统一 LLM 可调；这是本方案要新建的核心模块。

## 四、TTS 现状（明确回答，不可破坏）

- **已真实使用**：Voice Service（FastAPI :5015）调豆包语音 → 自动剪辑配音走此链路。
- 配置位置：`DOUBAO_SPEECH_*` 全在 `.env.local`（明文）；`providers/doubao.py` 读取；前端 `speech-voice-catalog.ts` 写死 10 个豆包音色。
- **无前端配置入口**；**无法运行时切换 Provider**（`get_provider()` 硬编码 Doubao）；**不支持声音复刻/自定义音色**（仅固定预设音色）。
- 设计约束：迁移到统一设置时**必须保持豆包可用**，新增 Provider（如未来声音复刻）走 `base.py` 抽象 + 注册表，不破坏现有 `/v1/tts`。

## 九、配置存储方案（A/B/C/D 比较 + 推荐）

| 方案 | 说明 | 优点 | 缺点 | 适配度（企业本地部署） |
|---|---|---|---|---|
| A `.env.local` | 当前做法 | 简单、gitignored | 明文、无 UI、无 RBAC、无掩码、改需重启、密钥散落 | ❌ 不应作为唯一存储 |
| B DB 加密字段 | 新增 `provider_settings` 表，secret 列 AES-256-GCM 加密；非密钥字段（base_url/model/enabled）明文 | 可 UI、可 RBAC、可审计、可掩码回显、热更新、与现有 SQLite/Drizzle 一致 | 需实现加密 + 主密钥管理 | ✅ **推荐为主存储** |
| C 本地加密 config | 加密 JSON/TOML（如 `config.encrypted.json`），密钥在 env | 密钥不落 DB、可随引擎迁移 | 难做 UI/RBAC/审计、MPT 已用明文 toml 不一致 | ◐ 可作 MPT 桥接补充 |
| D 系统 Keychain（Win Credential Manager / DPAPI） | 密钥存系统凭据库 | 操作系统级保护、防明文落盘 | 跨平台差、Python(MPT)读取复杂、便携性差 | ◐ 仅用于保护「主密钥」 |

**推荐（混合 B + D）**：
- **主存储 = 方案 B（加密 DB）**：所有 Provider 设置存 `provider_settings` 表；`api_key`/`secret`/`access_key`/`secret_access_key` 等列加密存储；`base_url`/`model_name`/`enabled`/`is_default` 明文。
- **主密钥来源 = 方案 D 思路**：`SETTINGS_MASTER_KEY` 默认从 env 读取；在 Windows 本地部署场景，可用 **DPAPI / Windows Credential Manager** 引导出主密钥（避免主密钥本身明文落盘）。MPT 子进程需要密钥时，由桥接层从 DB 解密后注入其 `config.toml` 或 env，**不在磁盘留明文**。
- **`.env.local` 收敛为仅引导项**：只保留 `DATABASE_PATH`、`VOICE_SERVICE_URL`、以及主密钥引用；现有 Doubao/Volcengine 真实密钥迁移进 DB 后从 `.env.local` 删除。
- **不入库即明文**：严禁任何新增密钥走 `.env.local`。

## 十、权限方案

- **查看/修改权限**：仅 `super_admin`。设置 API 路由与设置页均加 `actor.role !== 'super_admin' → 403`（复用 `getCurrentUser()` + 角色判断，与 `system/employees` 一致）。`manager`/`employee` **不出现该菜单、看不到任何 Key/Secret/Endpoint**。
- **Key 掩码**：前端仅显示掩码（如 `23b8•••••••••••9c2d`，保留前缀 4 + 后缀 4）；响应体里 secret 字段后端一律返回 `masked: true` + 掩码串，**绝不回显明文**。
- **Secret 不回显**：`GET /settings` 返回 secret 为掩码；仅「测试连接」「保存」时服务端用明文（从加密列解密到内存，不序列化出响应）。
- **测试连接**：`POST /system/settings/test`，服务端用存储（或本次提交）的密钥向 Provider 真实探测（如 `GET /v1/voices` 或 LLM `/chat/completions` 轻量请求），只返回 `ok/error/latency`，不返回密钥。
- **保存策略**：① 校验必填（启用即要求 key/base_url/model）；② 服务端加密后再写库；③ 写库成功后若涉及 MPT，异步桥接写其 `config.toml`（原子保存，参考 `config.py` 锁）；④ 操作记审计日志（谁、何时、改了哪个 module/key、启用/停用）；⑤ 失败回滚、不残留明文。

## 十二、模型切换机制

- 设置中心保存「Provider + API Key + Base URL + Model Name + is_default」。
- `src/lib/ai/index.ts` 在请求时读取「当前默认 LLM 设置」→ 选对应 `providers/*` 适配器 → 调 `chat()`。
- **业务代码不感知 Provider**：AI 聊天 / Agent / 自动剪辑脚本 / 知识问答 都只写 `await ai.chat(prompt, {type})`；换 DeepSeek→OpenAI→豆包阿k 只改设置，不改业务。
- 兼容接口：优先以「OpenAI Chat Completions 兼容」为统一适配基准（MPT 注册表里大多 Provider 即兼容），豆包 Ark / DeepSeek / 通义 等均可经同一适配器 + 不同 base_url 接入。
- 测试阶段手动配（满足用户示例：Provider=VolcEngine Ark、Key、Base URL、Model=doubao-xxx），后续切其它兼容接口零代码改动。

## 十四、风险项

| # | 风险 | 严重度 | 说明 |
|---|---|---|---|
| R1 | `.env.local` 明文密钥 | 高 | 4 个真实密钥明文落盘；迁移到加密 DB 前存在泄露面 |
