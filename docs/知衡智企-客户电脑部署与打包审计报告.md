## 0. 一句话结论

**当前开发项目不能直接拷贝给客户运行**——它缺 3 类东西:① 未安装/未打包的 Node 与 Python 运行时;② 未做 production 构建(现在跑的是 dev 缓存,`pnpm dev` 依赖开发模式);③ 没有「一键启动器」编排 Next.js / Voice Service / 视频引擎三个服务的启动顺序。但这三个服务**全部已有可复用的启动与管理代码**,从"能跑"到"客户双击能跑"的差距主要是**打包与编排**,不是功能缺失。

## 一、当前项目为什么不能直接拷贝运行(根因)

| # | 问题 | 详情 |
|---|---|---|
| 1 | **依赖开发模式的构建缓存** | `.next/dev` 占了 3.3G,是 `next dev` 的缓存;`next start` 需要 production 构建(`npm run build` / `BUILD_STANDALONE=true`)才有可运行产物。直接拷 dev 缓存不可行 |
| 2 | **客户机没有 Node.js** | 项目 `.nvmrc` = Node 22,当前用 v22.22.2。客户机不装 Node 无法跑 `next start`。Next 16.2.12 / React 19.2.4 / better-sqlite3 13.0.3(有 win32-x64 **prebuilt**,免编译) |
| 3 | **客户机没有 Python** | 需要 2 个 Python 环境:Voice Service(Python 3.12,`.venv-doubao` 31M)+ 视频引擎 MoneyPrinterTurbo(Python 3.11,`.venv` 737M) |
| 4 | **无一键启动编排** | 现在靠 `scripts/start-dev.ps1` 手动拉起 voice-service + `npm run dev`。客户需要 3 个独立启动 + 手动配端口 |
| 5 | **首次配置未产品化** | LLM Key / 豆包 TTS Key / 视频引擎素材 Key / 存储根目录都需要在首次启动时填写,目前只能手工改 `.env.local` / `config.toml` / 后台设置页 |
| 6 | **体积未裁剪** | 全量拷贝会把 3.3G dev 缓存、698M public/uploads 测试素材、521M 废弃 `.venv`(含 torch)全带上 |
| 7 | **数据污染** | 现有 `data/*.db`、`storage/`、`public/uploads` 是开发期数据,不应进客户包 |

## 四、交付方式判断(3 方案对比)

| 维度 | A. 便携版(解压+start.bat/launcher) | B. Windows 安装包(Setup.exe/MSI) | C. 桌面壳(Electron/Tauri) |
|---|---|---|---|
| 开发工作量 | **最小**(在现有 scripts + service-manager 上封装) | 中(需 Inno Setup/WiX + 打包 3 套运行时) | 大(Tauri/Electron 工程 + 进程管理集成) |
| 稳定性 | 高(纯本机进程,无壳层) | 高 | 中(壳层 + webview 兼容风险) |
| 客户使用难度 | 低(双击 .bat / .exe) | 低(安装向导) | 最低(桌面 App 图标) |
| 升级难度 | **低**(覆盖文件夹即可) | 中(重新装) | 低(壳内更新) |
| 本地服务管理 | 已有 `service-manager` 可直接复用 | 需集成服务注册 | 需在壳内做进程管理 |
| Voice Service | 随包 venv,launcher 拉起 | 同左 | 同左 |
| MoneyPrinterTurbo | 随包 venv,按需 spawn | 同左 | 同左 |
| Python 依赖 | 随包 venv(直接拷贝) | 随包 | 随包 |
| 后续维护 | **最简**(一份 launcher 脚本 + 目录替换) | 中 | 高(壳升级链路) |

**结论:现阶段选 A(便携版)最合适。**
- 现有 `scripts/start-dev.ps1` + `src/lib/service-manager/*`(auto-start/registry/voice-service 注册)+ `moneyprinter-engine.ts` 已覆盖 90% 的编排逻辑,只需补一个「生产模式」launcher(而不是 dev)。
- 客户是"解压即用"的本地企业软件,不需要注册表/服务安装。
- Tauri/Electron 壳属于**后期 Phase C 增强**(需桌面授权/自动更新时再加),现在加会显著拖慢交付。
- 建议:portable 版现在做;`launcher.exe` 用一个小型自解压/脚本包装(未来可换 Tauri)。

## 五、「一键启动」目标架构(Launcher)

```
双击 知衡智企.exe / start-zhiheng.bat
│
├─ 1. 检查/读取 config(首次安装向导)
├─ 2. 检查 Node(portable 或系统) → 失败:明确报错
├─ 3. 检查端口 3000/5015 → 冲突:报错退出
├─ 4. 数据库初始化:
│     data/ 空 → runMigrations() 自动建库建表
│     → 无 super_admin → init-admin(读首次向导填的账号)
├─ 5. 启动 Voice Service
│     .venv-doubao python uvicorn :5015
│     → health 就绪(≤60s)→ ✓ / 失败:提示
├─ 6. 启动 Next.js(production)
│     next start(或 standalone server.js)
│     → 等待 :3000 ready
├─ 7. 检查 MoneyPrinterTurbo
│     engines/.../.venv 存在 + config.toml 存在 → 按需启用
│     → FFmpeg:校验 imageio_ffmpeg 内置 → ✓(不需系统装)
├─ 8. 任一服务失败 → 打开错误弹窗(带日志路径)
└─ 9. 自动打开浏览器 http://127.0.0.1:3000(或 Tauri 窗口)
```

启动顺序:**DB → Voice → Web → Video(按需)**。服务间无强依赖(Web 启动失败不影响 Voice 已起),但 Web 是主入口,最后 ready 时开浏览器。

> 关键:生产 launcher 应调用 `next start` / standalone,而不是 `pnpm dev`(dev 需要源码热编译 + 会写 3.3G 缓存,不适合客户机)。

## 十五、16 项问题答案

1. **为什么不能直接拷贝运行?** 缺 Node/Python 运行时 + 只有 dev 缓存无 production 产物 + 无一键编排 + 首次配置未产品化(见 §一)。
2. **客户机缺哪些运行环境?** Node 22、Python 3.12+3.11(可随包 venv)、FFmpeg(随包内置,无需系统装);SQLite/浏览器/Redis/Docker/WSL 都不需要(见 §二)。
3. **几个必须启动的服务?** **3 个**:Next.js Web(3000)、Voice Service(5015)、MoneyPrinterTurbo(按需 spawn);SQLite 内嵌(见 §三)。
4. **最推荐的打包方式?** **A 便携版**(解压 + launcher.exe),基于现有 service-manager 扩展,工作量最小(见 §四)。
5. **一键启动器该做什么?** 检查配置→初始化 DB→起 Voice→起 Web→按需启视频引擎→检查端口→等 ready→开浏览器→失败弹窗(见 §五)。
6. **首次启动如何初始化?** `runMigrations()` 空库自动建表 + `init-admin` 创建 super_admin;已有,缺的是"首次向导 UI 取值"(见 §六)。
7. **哪些数据不需要迁移?** public/uploads、data/*.db、storage/、MPT storage/、现有 .env.local 的真实 Key(见 §八)。
8. **哪些配置需客户重填?** LLM/豆包 TTS/声音复刻/视频素材 的 API Key + Storage Root(可后台改);端口冲突时改端口(见 §七)。
9. **当前开发项目实际多大?** ≈ **6.7 GB**(.next 3.3G 是最大头)。
10. **客户运行版预计多大?** 最小 1.2-1.5G / 标准 1.9-2.2G(见 §九)。
11. **MoneyPrinterTurbo 占多大?** **973M**(venv 737M + resource 198M + storage 38M),可精简到 ≈450-550M(见 §十)。
12. **Voice Service 占多大?** 实际运行 venv 仅 **31M**(`_doubao`);另 521M `.venv`(torch)为废弃误装,不带(见 §十一)。
13. **Node / Python 各占多少?** Node(portable ≈60-80M,或 standalone 免带);Python 无需系统装,venv 合计 ≈**768M**(voice 31M + MPT 737M)。
14. **哪些目录可以不打包?** `.next/dev`(3.3G)、`public/uploads`(698M)、`.git`(142M)、`services/voice-service/.venv`(521M 废弃)、`data/`、`storage/`、MPT `storage/`、`frontend-base`、`docs`(可选)。
15. **Win10/11 最低硬件建议?** 4 核 CPU + 8G RAM + 10G 磁盘 + SSD;GPU 非必需(默认 CPU int8);Windows 10 21H2+ / 11(见 §十二)。
16. **到"客户双击即可运行"还差多少项工作?** **约 9 项**:① 生产构建(standalone)② 精简/装配便携目录 ③ 生产 launcher 脚本 ④ 首次向导(管理员+Key)⑤ 端口/环境预检 ⑥ 日志与错误弹窗 ⑦ 打包 zip/exe ⑧ 客户机验收(干净 Win10)⑨ 文档(安装/升级)(见 §十三 Phase B)。

## 十六、如果明天就要拿去客户电脑演示,最少做这 5 件事

1. **跑一次 production 构建并装配便携目录**:`npm run build`(standalone)→ 将 `.next/standalone` + `.next/static` + `public`(去掉 uploads)+ `src` 相关资源整理成 `dist/` 目录。
2. **写一个 `start-zhiheng.bat` / `launcher.exe`**:顺序拉起 voice-service(用 `.venv-doubao`,31M)+ 生产 `next start`,做端口检测 + 失败提示 + 自动开浏览器。**这是演示能跑的关键,工作量约 1 天。**
3. **随包带上两个 venv 并写首次初始化**:拷贝 `services/voice-service/.venv-doubao` + `engines/moneyprinterturbo/.venv`;launcher 首启时调 `runMigrations` + `init-admin`(向导填管理员账号)。**Voice Service 立即可用,AI 视频可用。**
