# 知衡语音 · 声音复刻 模块设计方案

> **设计范围**：在「知衡语音」一级菜单下新增「声音复刻」二级页面，复用现有 Voice Service 架构，纯新增能力，**不动音色库 / 音色列表接口 / TTS 流程**。
> **设计阶段**：第一阶段——分析 + 方案（不写代码）。
> **参考**：[豆包声音复刻页](https://www.volcengine.com/docs/6561/1309490)（标题 + 装饰波形 + 语种选择 + 上传/录制两枚按钮 + 「消耗一个音色席位」）。

## 一、页面设计方案

### 1.1 路由位置

- **路径**：`/dashboard/voices/clone`（用户建议采纳）
- **导航面板**：把 `知衡语音` 的 `items: []` 改成嵌套子项：

```ts
{
  title: '知衡语音',
  url: '/dashboard/voices',          // 音色库作为默认进站
  icon: 'music',
  items: [
    { title: '音色库',  url: '/dashboard/voices',      icon: 'library' },
    { title: '声音复刻', url: '/dashboard/voices/clone', icon: 'mic' }
  ]
```

> 为什么不沿用 `dashboard/settings` 那种「单页 + Tabs」？因为音色库和声音复刻是两套数据源、两种权限语义（音色库浏览只到 `workspace:view`，声音复刻至少要 `voices:manage`），且克隆有「我的声音资产 / 试听 / 默认 / 业务绑定」一整套列表态，塞 Tabs 会把页面拉得过长。

### 1.3 顶部提示条「音色席位」

> 这是豆包页直接抄过来的元素 + 我们企业的语义。对应豆包页 "复刻新音色消耗一个音色席位"。

- **位置**：Hero 上方，全宽卡片
- **组件**：`SlotQuotaCallout`（独立组件，便于后续接入真实席位表）
- **字段**：`quotaUsed / quotaTotal`，**一期硬编码 3**（不改后端），但 props 化便于后续接入计费
- **链接**：右侧「查看音色席位」跳 `/dashboard/account?tab=plans`（**链接可有可无**，一期可省）
- **状态文案**：
  - `used < total`：默认态
  - `used >= total`：红色 alert，"席位已满，请删除旧音色或升级套餐"

### 1.4 Hero 区「录制或上传音频」

> 完全沿用豆包页 hero 卡片的对称结构，每个元素一一对应。

| 区块 | 控件 | 复用 / 新建 | 说明 |
|---|---|---|---|
| 标题 + 副标题 | `<h2>` + `<p>` | 复用 Card | 直接对齐豆包文案 |
| 装饰波形 | SVG 静态图 | 新建 `WaveformDecoration` | 1 张 CSS / SVG，5 KB 内 |
| 语种选择 | `<Select>` | 复用 `Select` | 选项一期：`zh-cn / en-US / ja-JP`；跟从 `zhiheng-voice-page.tsx` 既有语言的取值 |
| 上传按钮 | `<Button variant=outline>` + `Upload` 图标 | 复用 `Button` | 触发 `<input type=file accept="audio/*">` |
| 录制按钮 | `<Button variant=primary>` + `Mic` 图标 | 复用 `Button` | 触发 `AudioRecorder.start()` |
| 录制中面板 | `<Card>` + 实时波形 + 时长 + `⏸ / ⏹ / 重录` | 新建 `RecordArea` | 时长 0.1s 刷新，UI 用 `requestAnimationFrame` |
| 预览面板 | `<Card>` + 波形 + `▶ / 替换 / 重录` | 新建 `PreviewArea` | 上传完或录完后展示 |

| 合规复选框 | `<Checkbox>` + `<Label>` | 复用 | **必勾**，否则按钮禁用 |

### 1.5 「我的声音资产」列表

> 企业扩展核心，是豆包页所没有的。

- **Tabs**：[全部 / 训练中 / 已就绪 / 失败]（一期不做"全部 + 已归档"拆分，archived 折叠到失败 tab）
- **栅格**：`grid-cols-1 md:grid-cols-2 xl:grid-cols-3 gap-4`
- **卡片 `CloneCard`**：
  - 标题：`display_name`
  - 元信息：语种 + 创建时间 + 时长（`duration_ms → 秒`）
  - **状态徽章**：`CloneStatusBadge`，按 `status` 着色
    - `draft`：灰 / `Badge variant=outline`
    - `uploading`：蓝 + `<Loader2 />` 旋转
    - `training`：蓝 + `<Progress indeterminate />`
    - `ready`：绿
    - `failed`：红 + hover tooltip 显示 `error_message`
    - `archived`：灰禁用
  - **试听**：`PreviewAudioPlayer`（迷你 `<audio controls>` + 进度条；试听的 URL 走 `GET /api/.../voices/clone/[voiceId]/preview`）
  - **默认声音**：`<Switch>`，"设为中文默认"（受 `voices:manage` 控制），勾选时调 `POST .../[voiceId]/default`
  - **业务可用**：`<Switch>`（受 `voices:manage` 控制），勾选时调 `PATCH .../[voiceId]/enable`，关联更新 `voice_catalog.enabled_for_production`
  - **绑定业务**：`<Button variant=link>`，「绑定到当前 workspace / 营销视频 / 客服话术」，**一期保留 UI 但路由返回 501**（"该能力即将上线"），便于后续接入业务绑定
  - **删除**：`<Button variant=ghost>` + AlertDialog 二次确认
- **空态**：用 `<Empty>`，插画 + 「您还没有复刻音色，去创建一个？」

### 1.6 复用 vs 新增 UI 清单

**复用现有**（来自 `src/components/ui/*` 和 `src/components/file-uploader.tsx`）：
- `PageContainer` / `Card` / `Button` / `Input` / `Textarea` / `Badge` / `Progress` / `Switch` / `Select` / `Checkbox`（如无，沿用 Label+input）
- `Dialog` / `Sheet` / `AlertDialog`（删除确认） / `DropdownMenu` / `Tooltip` / `Tabs` / `Empty` / `Skeleton`
- `sonner`（toast 通知）

**新建（前端）**：
- `src/components/icons.tsx` 注册新图标（按 `AGENTS.md:608-625` icon registry 规则）：
  - `mic` → `Mic` / `record` → `Disc3` / `wave` → `AudioWaveform` / `volume` → `Volume2` / `headphones` → `Headphones` / `library` → `Library`
- `VoiceClonePage`（client default export）+ 一系列 section 组件（详见三、组件拆分）
- **`AudioWaveform`（vanilla）**：
  - 用 `AudioContext.decodeAudioData(blob)` → 拿 `Float32Array`
  - `canvas` 绘制波形（peaks/LOD：每像素一个峰值）
  - 录制中：接 `AnalyserNode.getByteTimeDomainData()` → RAF 重绘
  - 播放头：监听 `audio.currentTime` 同步
  - 不引第三方库（**项目无 wavesurfer**）
- **`AudioRecorder`（vanilla）**：
  - 封装 `navigator.mediaDevices.getUserMedia({ audio: { channelCount: 1, sampleRate: 16000 } })`
  - 用 `MediaRecorder` 导出 `audio/webm;codecs=opus`（fallback `audio/wav` —— wav 12 KB/s @ 16kHz）
  - 提供 `{ start, stop, pause, resume, onTick, onStop }`
  - **核心 UX**：录制中持续回调 `(rmsDb: number, durationMs: number)` 给波形

### 1.7 主题与可访问性

- 浅色 / 深色主题自适应（用现有 `Card / Button` 已支持）
- 录制按钮 `<button aria-label="开始录制">` 屏读友好
- 所有图标 SVG `<svg aria-hidden />` （沿用 `lucide-react`）
- 输入框错误态走原生 `aria-invalid`

## 二、路由设计

### 2.1 页面路由

| 路径 | 模式 | 来源 | 描述 |
|---|---|---|---|
| `/dashboard/voices` | 服务端（RSC） | **已有** | 音色库（保持不动） |
| `/dashboard/voices/clone` | 服务端（RSC）+ client component | **新增** | 声音复刻 |

新增 page：`src/app/dashboard/voices/clone/page.tsx`

```tsx
// 顶层：跟 voices/page.tsx 镜像结构
export default async function VoiceCloneRoute() {
  const result = await requireWorkspacePermission(
    VOICE_WORKSPACE_SLUG, 'scripts:manage'   // 进站同 voices
  );
  if (!result.ok) return <WorkspaceAccessDenied />;
  const canManage = hasWorkspacePermission(
    result.context.user, result.context.membership, 'voices:manage'
  );
  return (
    <PageContainer>
      <VoiceClonePage workspaceSlug={VOICE_WORKSPACE_SLUG} canManage={canManage} />
    </PageContainer>
  );
}
```

- 进站以 `scripts:manage`（与 `/dashboard/voices` 一致）
- 操作项（设为默认 / 启用业务可用 / 删除）以 `voices:manage` 控制
- super_admin 通过 `hasEnterpriseAdminAccess` 自动放行

### 2.2 API 路由（Next.js，新建）

全部新建在 `src/app/api/workspaces/[workspaceSlug]/voices/clone/`，**不会污染** 现有 `voices/`、`voices/[voiceType]`、`voices/sync`、`voices/[voiceType]/preview`。

| Method | Path | 权限 | 说明 |
|---|---|---|---|
| POST | `/` | voices:manage | 创建复刻：上传样本 → 触发训练 → 返回 voiceRecord |
| GET | `/` | workspace:view | 列表（按 owner 过滤，super_admin 可见全部） |
| GET | `/[voiceId]` | workspace:view | 详情 |
| PATCH | `/[voiceId]` | voices:manage | 更新 name / language / description |
| DELETE | `/[voiceId]` | voices:manage | 删除 + 置 archived/取消业务可用 |
| GET | `/[voiceId]/preview?text=...` | workspace:view | 试听 mp3（流式回客户端） |
| POST | `/[voiceId]/default` | voices:manage | 设为该 owner 该 language 默认 |
| PATCH | `/[voiceId]/enable` | voices:manage | 业务可用 toggle（联动 `voice_catalog`） |
| POST | `/[voiceId]/bind` | voices:manage | 绑定到 workspace / 场景，**一期返回 501** |

### 4.1 设计原则

1. **不动** 现有 `/api/workspaces/[workspaceSlug]/voices/{route}`、`/voices/sync`、`/voices/[voiceType]`、`/voices/[voiceType]/preview`

### 4.2 Next API（`src/app/api/workspaces/[workspaceSlug]/voices/clone/`）

#### POST `/` 创建复刻

> 因为样本要先存盘再触发训练，分两步还是一步？**选一步上传**：multipart/form-data 一次提交 `audio` 字段 + 元数据，后端先存盘再同步触发训练。
> 借口给用户：训练是异步，返回时 status 已 = training。

```ts
Request: multipart/form-data
  Fields:
    audio: File (<= 8MB, mime in audio/wav|audio/mpeg|audio/mp4|audio/x-m4a|audio/webm)
    display_name: string (≤ 32 char)
    language: 'zh-cn' | 'en-US' | 'ja-JP'

Response 201:
  {
    id: string (UUID),
    status: 'training',

Errors:
  400 { error: 'AUDIO_TOO_LARGE' | 'AUDIO_TOO_SHORT' | 'AUDIO_TOO_LONG' | 'INVALID_FORMAT' | 'CONSENT_REQUIRED' | 'INVALID_NAME' }
  401 { error: 'UNAUTHORIZED' }
  403 { error: 'PERMISSION_DENIED' }
```

服务端行为：
1. 调用 `requireWorkspacePermission(slug, 'voices:manage')` 鉴权
2. busboy 解析流式写盘（参照 `automation/assets/route.ts:7-184`）
3. ffmpeg 探测时长（≥ 5s，≤ 60s），大小 ≤ 8MB
4. 写 `storage/voice-service/clone-samples/<userId>/<cloneId>.<ext>` （**不在 public/**，保证隐私）
5. 插表 `voice_clones` (status='training', sample_path, sample_filename, sample_size_bytes, sample_duration_ms, sample_format, consent_signed_at=now(), consent_signed_ip, ...)
6. 调 Python `POST /v1/voice/clone/train` → 拿 `task_id`，回写 `task_id`
7. 返回 201（不等待训练完成）

### 5.2 与 `voice_catalog` 的关系

> **核心问题**：`voice_catalog.voiceKind` 已经预留 `'cloned'`，但 `voice_catalog` 没有 `owner_id`，且设计上「音色库」对所有 video 生产者是统一的可见集合（仅按 `enabledForProduction` 过滤）。
> 故，**克隆结果不进 `voice_catalog` 主表**（避免混入所有用户的私有音色），而是通过 `voice_catalog_voice_type` 外键 + **业务可用时** 复制一份最小化信息到 `voice_catalog`：
>
> - `voice_clones.enabled_for_production=true`（owner 勾选「业务可用」）时：
>   - UPSERT voice_catalog：
>     - `voiceType` = `voice_clones.provider_voice_id`
>     - `voiceKind='cloned'`
>     - `displayName = voice_clones.display_name`
>     - `language = voice_clones.language`
>     - `enabledForProduction=true`
>   - 同时回写 `voice_clones.voice_catalog_voice_type`
> - `enabled_for_production=false`：
>   - UPDATE voice_catalog SET enabled_for_production=false WHERE voice_type=...
> - DELETE：
>   - **不**级联删除 voice_catalog 行（保留历史，防误删）
>   - 但 `enabled_for_production=false`，自然从视频生产下拉框消失

这样：
- `src/lib/voice-catalog.ts:listEnabledVoices()` 已会返回 `voice_kind='cloned'` 的行，**音色库页面无需任何改动**
- 视频生产可立即选择克隆音色
- 克隆音色仍归属 owner，能在 `/dashboard/voices/clone` 单独管理

## 七、风险与开放问题

1. **豆包侧 voice clone HTTP 接口签名**：本文不假设具体 URL，请求开发者先到 `DOUBAO_SPEECH_RESOURCE_ID=seed-tts-2.0` 对应控制台 / 文档查官方 voice clone HTTP endpoint；若只能用 WS，则 Python 端仍走 V3 WS（参考现有 `providers/doubao.py:18-53`）
2. **样本音频存储路径**：`storage/voice-service/clone-samples/<userId>/` —— 这是 `public/` 之外的「私有」路径，**不会被 Next.js 当静态文件暴露**；但要确保 `/api/.../preview` 鉴权后才会流回客户端
3. **样本合规审核**：豆包官方对音色复刻内容有审核要求，错误码需要在 UI 上分级展示（failed 时把 `error_message` 显示给用户）
4. **训练时长**：豆包侧训练可能 5-30s，前端 polling 策略：5-15s 内 2s 一次，15s 后 5s 一次，60s 后停止轮询（提示用户稍后刷新）
5. **`voice_catalog` 主键是 `voice_type`**：`provider_voice_id` 全 workspace 唯一这一点由 provider 保证（豆包 voice_id 全局唯一）；若未来引入多 provider，需要在 `voice_catalog` 加 `(provider, voice_type)` 复合键
6. **声纹合规**：项目 `AGENTS.md` 未明确要求 `consent_*` 落 DB，本文强烈建议**保留**（合规留痕）；审核 audit log 用现有 `sessions` 表 / 一期不另建
